Event priority should distinguish eligibility from urgency
I would introduce two separate concepts:
Eligibility: Can this event happen now? Determined by your existing triggers.
Priority: How desirable is it to play this event now?
For example:
Event Priority
Generic conversation with Emma Low
New mini-arc introduction Normal
Follow-up to yesterday's argument High
Emma waiting for a scheduled date Very high
Important event with a deadline Critical
This could eventually support a weighted selection system with some randomness.
One important distinction: eligible events shouldn't necessarily all play immediately. Otherwise, crossing a relationship threshold could suddenly trigger five consecutive events involving Emma.
I'd consider an event queue or director that distributes eligible events across periods, subject to narrative urgency and the player's available activities.
